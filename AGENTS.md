# partite-cli

The `partite` command line tool. It manages everything the terraform provider
(`../terraform-provider-partiteai`) manages, plus mesh versions and the runtime:
conversations, streaming and traces. It is built for people at a terminal and
for agents and scripts, so every command must work well in both.

## Layout

- `cmd/partite/main.go`: runs the root command and turns errors into exit codes.
- `internal/cmd/root`: the root command. `groups.go` lists every command group.
- `internal/cmd/<group>`: one package per top-level command, such as `apikey`.
  Each package exports `New(app *cmdutil.App) *cobra.Command`.
- `internal/cmdutil`: what every command shares. `App` has the context,
  clients and printer. Also errors and exit codes, name resolution, spec files,
  confirmation and the generic `Resource[T]` that builds list, get, delete and
  apply.
- `internal/graphql`: the GraphQL client. Operations are in `*.graphql`, one
  file per group. `generated.go` is generated by genqlient; never edit it.
  `inputs.go` has hand-written input types with `Optional[T]` for PATCH-style
  updates, copied from the terraform provider.
- `internal/auth`, `internal/credstore`, `internal/config`: login, stored
  secrets and contexts.
- `internal/output`: tables, JSON, YAML and id output.

Regenerate the client with `scripts/generate.sh`. It needs `../mesh` and
`../mesh-enterprise` beside this repo.

## Conventions for commands

Follow `internal/cmd/apikey` as the model.

- Commands are `partite <resource> <verb>`. Verbs are `list`, `get`,
  `create`, `update`, `apply`, `delete`, plus resource-specific ones.
- Every argument that takes an id also takes a name. Use
  `Resource.Resolve`, or `cmdutil.Resolve` for sub-resources.
- Each resource has one view struct with snake_case json tags. The field names
  are the terraform provider's attribute names. `get -o yaml` prints it and
  `-f` reads it, so that output can be edited and applied. Server-set fields
  (`id`, `created_at`, ...) are `omitempty` and ignored on input.
- Simple fields are flags. Nested or long fields come from `-f spec.yaml`.
  Flags that take long text or JSON accept `@file` and `@-` through
  `app.ReadValue`.
- `create` takes the name as its first argument. `update` changes only the
  flags that were passed (`cmd.Flags().Changed`).
- Output goes through `app.Printer()`. Lists use `List`, single objects use
  `Object`. Messages for people go through `Printer().Done`, which is silent for
  the json, yaml and id formats; those print data instead. Prompts and progress
  go to `app.Err`.
- Never prompt without a terminal. Destructive commands call `app.Confirm`,
  which needs `--yes` when there is no terminal.
- Return `*cmdutil.Error` with the right exit code and a hint when the user can
  do something about the error. Server errors are classified in
  `App.Classify`.
- Every command has a `Short`, and an `Example` when the usage is not obvious.
  Write help for someone who has never used Partite.
- Enterprise-only resources set `Resource.Enterprise`.

## Style

Write plainly: short sentences and the simplest exact words. Comment only what
the name and type do not say. Do not add one-line wrapper functions.

## Testing

Run a local mesh without auth, then point the CLI at it:

    PARTITE_CONFIG_DIR=$(mktemp -d) PARTITE_NO_KEYRING=1 \
    PARTITE_CONTEXT=local PARTITE_URL=http://127.0.0.1:18080 go run ./cmd/partite agent list

Do not leave built binaries in the repo; use `go run`.

`partite login` only logs in to Partite cloud. To log in to our dev
environment, make a context for it and point login at the dev Kinde business:

    partite context set dev --url https://api.dev.partite.ai --auth login
    PARTITE_OAUTH_ISSUER=https://auth.dev.partite.ai \
    PARTITE_OAUTH_CLIENT_ID=a9d0dac0a6804b57a0a9ac60f2cbf1cc \
    go run ./cmd/partite --context dev login

Refreshing needs no variables; the token URL and client id are saved with the
login.
